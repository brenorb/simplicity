# Eight additional native application scopes: feasibility audit

Scope audit dated 2026-11-05. Six listed applications are complete: the [Uniswap V2 pool](UNISWAP-V2-POOL.md), the [splitter](CUMULATIVE-SPLITTER.md), [Sablier stream](SABLIER-STREAM.md), [UMA bonds](UMA-BOND.md), [delegated governor](SNAPSHOT-GOVERNOR.md), and [quadratic funding round](QUADRATIC-FUNDING-SCOPE.md). Other rows describe the proposed bounds and qualify only after their own complete native vectors. The related compact native protocols have separate [current validation records](NATIVE-PROTOCOLS-VALIDATION.md).

The overlap inventory inspected all 128 IDs/titles in `reports/data/corpus-metadata.tsv`, the relevant published assumptions, and the complete five-entry `StatefulApps` source. The later BIP152 registration and the sibling-owned BIP32/BIP47/PSBT scopes were checked through team coordination. This is a complete comparison against that named snapshot and the named reservations, not a claim that every current repository or all DeFi protocols were reviewed. Selected primary files from seven repositories are retained as inert specification data in `vendor-specs/contract-extras/`, with exact commits, licenses and access gaps in `provenance.json`. Full untruncated tree discovery was used for Sablier, Nexus, OpenZeppelin and Gitcoin. This remains selected-module review; transitive dependencies and all external integrations are not yet audited.

Every feasible native adaptation must have one bound aggregate witness, authenticated actual funding, exact payments and continuation script, a complete committed ownership/balance/supply ledger, checked arithmetic, same-CMR negative vectors, and an explicitly initialized UTXO lineage. Serialized state prevents replay within that lineage; it does not establish a global registry across separately initialized deployments. Plumbing and math helpers receive no separate counting credit.

| **Budgeted quadratic-funding round with persistent per-person contributions** | [Buterin–Hitzig–Weyl, arXiv:1809.06421v2](https://arxiv.org/html/1809.06421v2), especially sections4 and5.1: funding based on squared sums of square roots, with budgeted matching. [Gitcoin MatchPayouts](https://github.com/gitcoinco/matching_contracts/blob/ae4e44e912531669a8115386ffd97af2f47f9fd1/contracts/MatchPayouts.sol) is only a payout-layer comparison: it accepts approved amounts and does not calculate quadratic matching. | Assurance crowdfunding uses a threshold and refunds; this scope computes a nonlinear allocation from per-identity contribution history and a finite sponsor pool, then consumes each project payout once. An authorized precomputed payout table alone would not qualify. | Fixed three identified donors/two projects. Native quantized profile stores integer voice units `v`, cumulative donor cost `v²`; increasing units charges `vNew²-vOld²` so split increments cannot buy votes cheaply. Compute each project's raw matching = `(sum v)² - sum(v²)`, prorate a funded sponsor budget with explicit floor/dust rule, close/finalize/claim once. Test split contributions, cross-project replay, budget exhaustion, zero matching denominator, inflated allocation and duplicate payout. | **Conditional feasibility; source/rounding gate remains.** This is an exact perfect-square contribution domain and stated native finite-budget policy, not general real-valued QF or a claim of current Gitcoin calculator compatibility. Confirm the normalization against the paper and define remainder/refund ownership before implementation. Fixed authenticated identities do not prove global Sybil resistance. |

The eight rows are candidate application groups, not a promise of eight count credits. A source discrepancy, failed dataflow review, overlap, or missing meaningful vectors keeps the row uncounted. BIP32 public derivation/rolling wallets are excluded because the Bitcoin agent owns that group. A simple RFQ was excluded as a subset of the new signed CoW order registration/cancellation/fill ledger; a simple NFT purchase duplicates the compressed-asset ownership plus existing sale families; a second Pendle LP path belongs to the already requested complete Pendle market group.

The source license map is per retained version. Sablier's main README is not used to override the actual pinned source SPDX and license files. The Gitcoin tree has no repository LICENSE; no redistribution grant is inferred for its reference-only materials. The arXiv paper has its stated non-exclusive distribution license; this audit links it and implements no downloaded paper code.
