## Counting and witness-flow validation

Only complete `Entry` programs passing the actual Bitcoin evaluator and commitment-invariance checks can count. Alias-sensitive code must materialize each logical witness once and then use projections; repeating the Haskell expression `witness x` does not constrain those copies to be equal at the same CMR. This requirement applies equally to programs adapted from a high-level source. See the root witness audit and `Regression/WitnessState.hs` for an executed state-counter attack and its repair.
