Each request enters as a singleton batch and locks the actual nominal BTC amount from the second input. Its derived share amount is `floor(3 * nominal / 4)`, a fixed native instance of the source `getSharesByPooledEth` conversion. Request IDs increase from one to two and cannot be reused. The fixed finalization authority signs an end ID and E27 rate through the actual successor state. The program advances from the last finalized ID through that end ID, assigning the checkpoint and exact claim amount to each newly finalized request. It leaves earlier checkpoints untouched. Current owners may transfer pending or finalized requests between the two configured keys. A finalized request may be claimed in either order by its current owner. The exact payout and its recipient script are enforced, and the claimed marker prevents transfer or payout from that request again.

The source computes `shareRate = floor(nominal * 10^27 / shares)`. If that integer exceeds the checkpoint, it pays `floor(shares * checkpoint / 10^27)`. Otherwise it pays the nominal amount. The program uses the equivalent checked comparison `nominal * 10^27 >= (checkpoint + 1) * shares` and computes the quotient on the discount branch. For nominal 1001, shares 750, and checkpoint `floor(1001 * 10^27 / 750)`, the source pays 1001. The naïve minimum formula pays 1000. The serialized cash balance equals unfinalized nominal value plus finalized unclaimed payouts plus realized surplus.
