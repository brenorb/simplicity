# Native virtual-reserve launch and migration

The app-virtual-reserve-launch corpus entry models a finite sale of funded Bitcoin vouchers. A sponsor funds the full inventory before trading starts. The curve uses virtual balances for its quotes, actual BTC for cash movements, and a fixed real inventory for sellout. Once the inventory runs out, both trade directions stop. Anyone can then trigger the exact migration payment. Holder vouchers remain backed until they redeem.

## Source profile

The source is the Pump program at public-docs revision 639b87fb45c3adeffa6f7c4a1bf0cb85e392bf22 and the official Rust SDK 0.4.1. Pump's source description establishes paired movements of real and virtual reserves, exact-base buys, exact-base sells, a completed flag at zero real inventory, and permissionless migration from a completed curve. The SDK gives the exact integer buy and sell rounding and ceiling fee. Its native-quote migration projects the remaining base inventory and real quote minus the configured migration fee. The reference preserves those parts of the lifecycle. [Pinned Pump program documentation](https://raw.githubusercontent.com/pump-fun/pump-public-docs/639b87fb45c3adeffa6f7c4a1bf0cb85e392bf22/docs/PUMP_PROGRAM_README.md), [pinned IDL](https://raw.githubusercontent.com/pump-fun/pump-public-docs/639b87fb45c3adeffa6f7c4a1bf0cb85e392bf22/idl/pump.json), [SDK quote source](../vendor-specs/pump-launch/pump-rust-client-0.4.1-bonding_curve.rs), [SDK fee source](../vendor-specs/pump-launch/pump-rust-client-0.4.1-fees.rs).

| Rule | Bounded native realization |
| --- | --- |
| Initial reserve parameters | 100 real sale vouchers plus 20 reserved for migration. Virtual base is remaining sale inventory plus 30. Virtual quote is the actual quote reserve plus 100,000 sats. Real quote starts at zero. |
| Exact-base buy | With quantity q, virtual quote x and virtual base y, reserve credit is floor(q × x / (y − q)) + 1. Buyer funds that amount plus the ceiling 100-bps fee. The max cost covers both. The fee is a separate exact output. |
| Exact-base sell | The reserve debit is floor(q × x / (y + q)). The seller owns q vouchers and receives the debit minus the ceiling 100-bps fee. The payout meets the minimum. The fee is a separate exact output. |
| Completion | The last exact buy makes remaining real sale inventory zero. Later buys and sells fail. The two registered owners can still transfer their vouchers. |
| Migration | At sellout, a permissionless spend moves all quote minus 5,000 sats and the BTC representing the 20 reserved migration vouchers to a fixed handoff script. It pays the exact 5,000-sat fee separately. The successor preserves both holder balances and enters the nontrading redemption phase. |
| Redemption | Each issued voucher redeems for its exact 5,000 sats of sponsored backing. The final holder spend pays its payout and returns the 10,000-sat state carrier to the sponsor, ending the state lineage. |

The buy is the exact-base quote. Its floor-plus-one rule also applies when the quotient is an integer. The inverse quote in the SDK and the source exact-quote-in instruction have their own rounding. The profile excludes partial fills, synthetic overflow fills, dynamic fee tiers, creator/cashback fees, foreign token accounting, and subsequent PumpSwap trading or LP issuance. The fixed 100-bps rate follows the legacy example. The fixed BTC fee, voucher sponsorship, two holders, and handoff script are native policy choices. The handoff pays the native liquidity and the migration inventory's funded representation. An external pool is outside this state machine.

## Bitcoin effects

An initialized outpoint defines the launch lineage. The dormant UTXO holds a 10,000-sat carrier. The sponsor signs and provides the exact 600,000 sats of voucher backing. While trading, the state UTXO carries that backing, the carrier, and the actual quote reserve. The virtual offsets are never spendable. Real quote is capped at 2,000,000 sats, and all arithmetic uses checked Word32 operations.

One typed witness contains the old 32-byte ledger, the requested action, and its signature field. The ledger has eight big-endian words for phase, remaining inventory, Alice's balance, Bob's balance, quote reserve, and three zero reserved words. The pure kernel derives the successor and exact outputs. The committed Taproot opening and the actual input 0 script must both match. There are exactly two distinct prevouts, with the second input funding an exact 1,000-sat miner fee plus any buy or sponsorship credit. The sponsor and both holders sign actual sig_all_hash when their actions require authorization. Migration is permissionless and fixes every output. The checks bind the actual scripts and amounts for the state continuation, protocol fees, holder payments, migration handoff and final carrier return.

## Validation

The independent Integer model checks value conservation across each transition. The primary fixture funds 600,000 sats, executes three buys and one sell, transfers vouchers, and reaches zero unsold inventory with 333,338 sats of real quote. Permissionless migration moves 428,338 sats to the handoff and 5,000 sats to the fee recipient. The owners transfer again, redeem 250,000 sats each, and return the 10,000-sat carrier to the sponsor on the final spend. The negative fixtures include a complete-shaped pre-sellout migration and an otherwise funded post-sellout sale, as well as incorrect authorization, rounded amounts, holder allocation and terminal outputs.
