# Constructibility of the shared representation premises

Branch `claude/shared-obligations` (fork point `a8685146`). Unregistered
support results: no coverage is added and no existing predicate, contract or
module is edited.

## Question answered

Every local jet contract takes a represented input frame and a writable
output frame as premises; `jet_context` takes a represented Bit Machine state.
These are legitimate *input requirements* only if they do not exclude inputs
or states that the canonical semantics admits. The results below show they
exclude nothing but sizes beyond the address space, and that the contracts
are not vacuous on any input.

## Limits

- Existence of *a* representing memory, not a proof that `eval.c` builds this
  one; the layout mirrors it (two allocations, consecutive frames) but the
  evaluator is not part of any proof translation unit.
- For the 36 Bitcoin jets the environment relation is a premise: a memory
  representing the logical environment is assumed, not constructed, and a
  footprint block that does not exist in the starting memory is excluded
  (a stored pointer does not make its target block valid).
- The 3 secp contracts live in the secp translation unit and are not
  instantiated.
- Sizes: cells ≤ `Int64.max_unsigned` per frame premise (already required by
  the contracts); `bm_state_fits` for whole states.
